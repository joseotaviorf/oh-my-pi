Cluster Spec Recommender — Decision Tree

Bidirectional, cost-truthful cluster right-sizing for bi-etl-ejuice DAGs. Source of truth: scripts/recommend_cluster_specs.py (classify() / _decide_multi()).

For each DAG it builds the feasible candidate shapes, prices them under one model (on-demand driver + spot workers + fleet DBU; NVMe stripped; Photon priced both kept and dropped across original and right-sized shapes), and keeps the cheapest that beats observed cost within SLA. The cohort is the reason for the pick.

How it decides — at a glance

For each DAG the tool looks at the cluster that actually ran the job (driver + worker instance types, worker count) and the utilization it observed over recent runs (CPU and memory, plus wall-clock time against the schedule). It is bidirectional: it builds the candidate shapes (collapse to one node, or a smaller multi-node with a small on-demand driver + spot workers), prices them under one model, and keeps the cheapest that beats today's cost without missing the SLA. Neither single-node nor multi-node is privileged. Follow the arrows — each box is a question about the workload, and the coloured boxes are the resulting recommendation.

The sections below restate this same flow with the exact metric names, thresholds, and cohort labels used in the code.

Build candidate A — collapse to single (build_best_single_candidate)
Additive demand: required_mem = Σ(node_mem × mem_p95); required_cores = Σ(node_vcpu × cpu_eff), cpu_eff = p50 + 0.3·(p95−p50) — memory is the only hard cap, CPU is elastic. Cheapest node holding mem ≤ 82% and cores ≤ 85%. Family from GiB/core demand; compute family excluded for keep-Photon candidates (Databricks rejects Photon on c*).
Build candidate B — refined multi (build_current_refined_candidate)
Independent levers: minimize the driver, resize the worker type/count (floor of 2 workers). Returns None when worker_count < 2 (1-worker clusters compete on collapse only). Must be a genuine reduction in driver, worker type, or count.
Filter each candidate
core cap: candidate cores ≤ observed cores (never upsize). SLA: projected p95 wall × (1 + f·(old_cores/new_cores − 1)), f = p50-busy fraction, must fit max(80% interval, wall_p95) — applied only when schedule interval ≤ 120 min; all other DAGs have no wall cap (the cost gate prices the inflated wall). Memory feasibility for collapse.

3 · Normalizations & the actions trace

Local NVMe is stripped on every actionable recommendation (drop_nvme swaps *gd→*g whenever is_any_local_nvme; spill DAGs are parked upstream). Photon is a costed dimension, not an unconditional strip: the recommender prices keeping it (raw demand, observed wall, observed-anchored DBU) and dropping it (effective_demand() CPU ×1.20 / memory ×1.30, wall ×2.0, non-Photon fleet DBU) across the original and right-sized shapes, and only emits disable_photon + runtime_engine: STANDARD when dropping wins. Observed CSV columns stay raw. When dropping the accelerators is the win it surfaces as an actionable right_size_multi/healthy_single with a real delta and validation YAML; a keep_multi_* pick is a true no-change (Photon/NVMe kept) and emits no validation. Recommended workers are always spot — the tool never emits ON_DEMAND. The cohort says which candidate won (or why none did); the actions column is the decision trace.
