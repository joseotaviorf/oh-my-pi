How it decides — at a glance

For each DAG the tool looks at the cluster that actually ran the job (driver + worker instance types, worker count) and the utilization it observed over recent runs (CPU and memory, plus wall-clock time against the schedule). The guiding bias is single-node-first: a multi-node Spark cluster is treated as a cost smell unless the measured demand proves it genuinely needs more than one machine. Follow the arrows — each box is a question about the workload, and the coloured boxes are the resulting recommendation.
